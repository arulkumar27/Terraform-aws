# Amazon S3 (Simple Storage Service)

## Overview

Amazon Simple Storage Service (S3) is AWS's highly scalable object storage service used to store and retrieve any amount of data from anywhere. It provides **11 9's (99.999999999%) durability**, high availability, security, versioning, lifecycle management, and encryption.

Terraform allows you to provision and manage S3 buckets as Infrastructure as Code (IaC).

---

# Why We Use S3

- Store images, videos, and documents
- Host static websites
- Store application logs
- Backup and disaster recovery
- Terraform Remote State
- Data Lake
- Software package storage
- CloudFront origin
- Media storage
- Big Data analytics

---

# Real-Time Use Case

A company hosts an e-commerce application.

- Product images are stored in S3.
- CloudFront serves images globally.
- Application logs are stored in another S3 bucket.
- Daily database backups are uploaded automatically.
- Terraform state files are stored securely in an S3 backend.

Terraform provisions all S3 buckets with encryption, versioning, lifecycle rules, and security settings.

---

# How Amazon S3 Works

```
              Users
                 │
                 ▼
          Amazon S3 Bucket
                 │
     ┌───────────┼───────────┐
     ▼           ▼           ▼
 Images      Documents      Logs
```

Objects are stored inside **Buckets**.

Each object consists of:

- Key (Object Name)
- Value (Data)
- Metadata
- Version ID (if versioning enabled)

---

# Bucket

A bucket is a container that stores objects.

Example

```
company-backups

project-images

terraform-state

application-logs
```

Bucket names must be globally unique.

Terraform Resource

```hcl
resource "aws_s3_bucket" "main" {

  bucket = "my-company-storage"

}
```

---

# Objects

Objects are the actual files stored inside the bucket.

Examples

```
logo.png

invoice.pdf

backup.zip

video.mp4

index.html
```

Maximum object size

```
5 TB
```

---

# Storage Classes

## Standard

Used for frequently accessed data.

Examples

- Website images
- Applications
- Active files

Advantages

- High availability
- Low latency

---

## Standard-IA

Infrequent Access.

Used for

- Monthly reports
- Backups

Lower storage cost

Higher retrieval cost

---

## One Zone-IA

Stores data in a single Availability Zone.

Suitable for

- Secondary backups
- Non-critical data

---

## Intelligent-Tiering

Automatically moves objects between storage tiers based on access patterns.

Advantages

- Cost optimization
- No manual lifecycle management

---

## Glacier Instant Retrieval

Used for archived data requiring immediate retrieval.

---

## Glacier Flexible Retrieval

Suitable for long-term backups.

Retrieval time

Minutes to hours.

---

## Glacier Deep Archive

Cheapest storage option.

Retrieval time

Up to 12 hours.

Suitable for

- Compliance
- Long-term archival

---

# Bucket Versioning

Versioning keeps multiple versions of an object.

Example

```
report.pdf

↓

Version 1

↓

Version 2

↓

Version 3
```

Terraform

```hcl
resource "aws_s3_bucket_versioning" "main" {

  bucket = aws_s3_bucket.main.id

  versioning_configuration {

    status = "Enabled"

  }

}
```

Benefits

- Recover deleted files
- Rollback changes
- Protect against accidental deletion

---

# Server Side Encryption

Encrypts data stored in S3.

Terraform

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "main" {

  bucket = aws_s3_bucket.main.id

  rule {

    apply_server_side_encryption_by_default {

      sse_algorithm = "AES256"

    }

  }

}
```

Options

- SSE-S3
- SSE-KMS
- SSE-C

Best practice

Use SSE-KMS in production.

---

# Public Access Block

Blocks accidental public access.

Terraform

```hcl
resource "aws_s3_bucket_public_access_block" "main" {

  bucket = aws_s3_bucket.main.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true

}
```

Always enable for private buckets.

---

# Bucket Policy

Defines who can access the bucket.

Example

```json
{
  "Version":"2012-10-17",
  "Statement":[
    {
      "Effect":"Allow",
      "Principal":"*",
      "Action":"s3:GetObject",
      "Resource":"arn:aws:s3:::website/*"
    }
  ]
}
```

Terraform

```hcl
resource "aws_s3_bucket_policy" "main" {

  bucket = aws_s3_bucket.main.id

  policy = data.aws_iam_policy_document.bucket.json

}
```

---

# Lifecycle Rules

Automatically move or delete objects.

Example

```

↓

Standard IA

↓

90 Days

↓

Glacier

↓

365 Days

Delete
```

Terraform

```hcl
resource "aws_s3_bucket_lifecycle_configuration" "main" {

  bucket = aws_s3_bucket.main.id

}
```

Benefits

- Reduce storage costs
- Automatic data management

# Static Website Hosting

S3 can host static websites.

Example

```
HTML

CSS

JavaScript

Images
```

Terraform

```hcl
resource "aws_s3_bucket_website_configuration" "main" {

  bucket = aws_s3_bucket.main.id

    suffix = "index.html"

  }

}
```

Usually combined with

- CloudFront
- Route53
- ACM Certificate

Advantages

- Compliance

Requirements

Used for

# Best Practices

- Enable versioning.
- Enable encryption.
- Block public access unless required.
- Use lifecycle rules to reduce costs.
- Use bucket policies instead of ACLs.
- Enable server access logging.
- Store Terraform state in a dedicated bucket.
- Use unique bucket names.
- Enable MFA Delete for critical buckets.
- Use CloudFront instead of making buckets public.

---

# Common Mistakes

- Leaving buckets public.
- Not enabling versioning.
- Forgetting encryption.
- Hardcoding bucket names.
- Storing sensitive data without access controls.
- Ignoring lifecycle rules, increasing storage costs.
