# Amazon EC2 (Elastic Compute Cloud)

## Overview

Amazon EC2 (Elastic Compute Cloud) is a virtual server service provided by AWS that allows users to launch, manage, and scale compute instances on demand. Terraform provisions EC2 instances as code, enabling repeatable, version-controlled, and automated infrastructure deployments.

---

## Why We Use EC2

- Deploy web applications
- Host backend APIs
- Run databases (small workloads)
- Build CI/CD servers (Jenkins, GitLab)
- Host Docker containers
- Kubernetes worker nodes
- Bastion hosts
- Monitoring servers
- Development and testing environments

---

## Real-Time Use Case

A company is deploying a three-tier web application.

- Application Load Balancer receives user traffic.
- EC2 instances host the frontend application.
- Auto Scaling launches additional EC2 instances during high traffic.
- Private EC2 instances run backend services.
- RDS stores application data.
- CloudWatch monitors EC2 health and performance.

Terraform creates all EC2 instances automatically without manually launching them from the AWS Console.

# EC2 Components

## AMI (Amazon Machine Image)

An AMI is a preconfigured operating system image used to launch an EC2 instance.

Examples:

- Amazon Linux 2023
- Ubuntu 22.04
- Red Hat Enterprise Linux
- Debian
- Windows Server

Terraform references an AMI using its AMI ID.

Example:

```hcl
ami = "ami-0dee22c13ea7a9a67"
```

---

## Instance Type

Defines the CPU, RAM, networking performance, and storage capabilities of the EC2 instance.

Examples

| Instance | Purpose |
|-----------|----------|
| t2.micro | Free Tier testing |
| t3.micro | Development |
| t3.small | Small applications |
| t3.medium | Medium workloads |
| m5.large | Production servers |
| c5.large | Compute intensive |
| r5.large | Memory intensive |

Example

```hcl
instance_type = "t2.micro"
```

---

## Key Pair

A Key Pair provides secure SSH access to Linux instances.

Terraform only references an existing key.

```hcl
key_name = "terraform-key"
```

Without a valid key pair, SSH access is not possible.

---

## Security Group

Acts as the firewall for the EC2 instance.

Example

- SSH → Port 22
- HTTP → Port 80
- HTTPS → Port 443

Terraform attaches the security group during instance creation.

```hcl
vpc_security_group_ids = [aws_security_group.web.id]
```

---

## Subnet

Determines where the EC2 instance will be launched.

Public subnet

- Has Internet Gateway access
- Used for web servers
- Receives public IP

Private subnet

- No direct internet access
- Used for application servers
- Accesses internet through NAT Gateway

Example

```hcl
subnet_id = aws_subnet.public.id
```

---

## Public IP

A public IP allows internet connectivity.

```hcl
associate_public_ip_address = true
```

Usually enabled for

- Bastion Host
- Web Server

Usually disabled for

- Database Server
- Backend Server

---

## Elastic IP

Elastic IP is a static public IP.

Advantages

- Fixed IP address
- Can be reattached
- Suitable for production

Terraform Resource

```hcl
resource "aws_eip" "main" {}
```

---

## Root Volume

The operating system disk attached during launch.

Example

```hcl
root_block_device {
  volume_size = 20
  volume_type = "gp3"
}
```

---

## User Data

User Data runs automatically during the first boot.

Common uses

- Install packages
- Update OS
- Install Docker
- Install Nginx
- Clone Git repository
- Configure application

Example

```hcl
user_data = file("userdata.sh")
```

---

## Tags

Tags help organize AWS resources.

Example

```hcl
tags = {
  Name = "Web-Server"

  Project = "Ecommerce"
}
```

# Common Arguments

| Argument | Purpose |
|-----------|----------|
| ami | Operating System Image |
| instance_type | EC2 Size |
| subnet_id | Launch Subnet |
| key_name | SSH Key |
| associate_public_ip_address | Public IP |
| vpc_security_group_ids | Attach Firewall |
| iam_instance_profile | Attach IAM Role |
| user_data | Bootstrap Script |
| tags | Resource Identification |

---

# Complete Example

```hcl
resource "aws_instance" "web" {

  ami                         = "ami-0dee22c13ea7a9a67"
  instance_type               = "t2.micro"
  subnet_id                   = aws_subnet.public.id
  key_name                    = "terraform-key"
  associate_public_ip_address = true

  vpc_security_group_ids = [
    aws_security_group.web.id
  ]

  root_block_device {
    volume_size = 20
    volume_type = "gp3"
  }

  user_data = file("userdata.sh")

  tags = {
    Name = "Web-Server"
    Environment = "Development"
  }
}
```

# Best Practices

- Never hardcode AMI IDs across regions.
- Use variables for instance type.
- Attach IAM Roles instead of storing AWS credentials.
- Keep instances in private subnets whenever possible.
- Enable monitoring.
- Use encrypted EBS volumes.
- Apply meaningful tags.
- Store user data scripts separately.
- Avoid using the root user.
- Use Launch Templates for production deployments.

# Common Interview Questions

### What is EC2?

EC2 is a virtual server service in AWS used to run applications on demand.

---

### What is an AMI?

An AMI is a machine image containing the operating system and software required to launch an EC2 instance.

---

### Difference between Public and Private EC2?

Public EC2 has a public IP and is internet accessible.

Private EC2 has only a private IP and is accessed through a Bastion Host or Load Balancer.

---

### What is User Data?

A startup script executed automatically when the EC2 instance launches for the first time.

---

### What is the purpose of Key Pair?

It provides secure SSH authentication for connecting to Linux EC2 instances.

---

### Which Terraform resource creates an EC2 instance?

```hcl
aws_instance
```
